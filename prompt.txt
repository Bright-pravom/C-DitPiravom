# MASTER DEVELOPMENT PROMPT

# C-DIT Computer Education — Modern Institute Website

You are an expert senior UI/UX designer, frontend engineer, interaction designer, accessibility engineer, SEO specialist and performance engineer.

Your task is to design and build a **complete, polished, production-quality website for C-DIT Computer Education**.

Do not create a generic template.

Do not create something that looks obviously AI-generated.

Do not simply assemble common landing-page sections.

The website must feel like a real, carefully designed **modern computer education institute website** serving students, parents, beginners, professionals and local learners.

---

# 1. CORE OBJECTIVE

Build a responsive website that communicates:

* Computer education
* Practical technology learning
* Career-oriented skill development
* Student guidance
* Digital literacy
* Programming education
* Creative/digital skills
* Website creation and digital services
* A trustworthy physical institute
* A welcoming learning environment

The website should answer three questions immediately:

1. What is this?
2. What can I learn/get here?
3. How do I contact/enquire?

The website should make a visitor feel:

> "This is a real, modern, approachable computer education institute where I can learn practical skills."

---

# 2. VERY IMPORTANT DESIGN PHILOSOPHY

The design must be:

* Light
* Bright
* Modern
* Professional
* Educational
* Friendly
* Trustworthy
* Technology-oriented
* Spacious
* Visually interesting
* Highly responsive

It must NOT feel:

* Dark
* Corporate-heavy
* Overly futuristic
* Neon
* Gaming-oriented
* Excessively glassmorphic
* Like a SaaS dashboard
* Like an AI startup landing page
* Like a generic Bootstrap template
* Like an over-designed Dribbble concept

The institute serves real students and parents.

The design should balance:

**modern technology + human education + local trust**

# 4. COLOUR USAGE RATIO

Do NOT make everything blue.

Approximate visual balance:

```text
70% white / very light backgrounds
20% blue / light-blue elements
8% dark typography
2% cyan/accent
```

Blue should provide identity and interaction, not overwhelm the interface.

The website should predominantly feel **light and clean**.

---

# 5. TYPOGRAPHY

Use a modern, highly readable sans-serif font system.

Recommended:

```text
Primary:
Inter
```

or another excellent modern sans-serif if Inter is unavailable.

Use strong typography hierarchy.

Example:

```text
Hero heading:
large / bold / tight line-height

Section heading:
large / bold

Card heading:
medium / semibold

Body:
comfortable reading size

Metadata:
smaller / muted
```

Avoid excessive font weights.

Use typography to create visual hierarchy rather than adding decorative elements everywhere.

---

# 6. GENERAL LAYOUT SYSTEM

Use a consistent maximum content width.

Recommended:

```text
max-width: 1200–1280px
```

The exact value may be adjusted according to the implementation.

Use generous horizontal spacing on desktop.

On mobile:

* Reduce padding
* Preserve readable line lengths
* Avoid horizontal overflow
* Maintain comfortable touch targets

All sections must align to a consistent content grid.

Do not allow every section to have a completely different width.

---

# 10. GLOBAL ANIMATION SYSTEM

Animation is important.

However:

**Do not animate everything.**

Animations must communicate hierarchy and polish.

Use:

* Fade
* Translate
* Scale
* Stagger
* Clip reveal
* Subtle parallax
* Hover elevation
* Image zoom

Avoid:

* Constant spinning
* Excessive bouncing
* Random floating objects
* Huge transitions
* Long delays
* Animation that blocks content
* Animation that makes reading difficult

---

* Cards must remain readable
* Horizontal overflow must not occur
* Gallery must remain performant
* Filters must be easy to operate
* Contact information must be one tap away
* Phone links should be clickable
* WhatsApp link should be clickable if available

---

# 82. DESKTOP REQUIREMENTS

On desktop:

* Use whitespace effectively
* Use hover interactions
* Use richer compositions
* Allow larger typography
* Use multi-column grids
* Use subtle image interactions
* Use more sophisticated visual hierarchy

Do not simply stretch mobile cards across the screen.

---

# 83. ERROR STATES

Design:

### No course results

```text
No courses found

Try changing your search or filters.

[Clear Filters]
```

### Gallery empty state

Only if needed.

### Form error

Clearly identify the problematic field.

### Form success

Provide clear confirmation.

Never silently fail.

---

# 84. LOADING STATES

Avoid unnecessary loading screens.

The main website should render quickly.

For dynamic content, use subtle skeleton/loading states only where they genuinely improve UX.

Do not display:

> Loading...

for the entire website.

---

# 85. 404 PAGE

Create a friendly 404 page.

Example:

> Looks like this page took a wrong turn.

Then:

```text
[ Back Home ]
[ Explore Courses ]
```

Keep it on-brand.

---

# 86. MICROCOPY

Use simple human language.

Prefer:

> Explore Courses

over:

> Discover Our Comprehensive Educational Solutions

Prefer:

> Get in Touch

over:

> Initiate a Communication Request

Avoid corporate jargon.

The institute should sound approachable.

---

# 87. TRUST DESIGN

Trust should come from:

* Real photographs
* Clear information
* Actual course details
* Physical address
* Contact information
* Consistent branding
* Transparent policies
* Professional design

Do not manufacture trust with fake testimonials, ratings or statistics.

---

# 88. DO NOT OVERDESIGN

Avoid:

* Every section having gradients
* Every card having glass effects
* Huge text everywhere
* Random floating blobs
* Excessive shadows
* Too many icons
* Too many badges
* Endless animation
* Excessive rounded corners

The site should remain clean after all content is inserted.

---

# 92. DO NOT CREATE FAKE CONTENT


# 97. CARD SYSTEM

Cards should share a consistent design language.

Default:

```text

```

Avoid excessive card nesting.

Do not put cards inside cards inside cards.

# 98. BORDER RADIUS

Use a consistent radius system.


# 99. SHADOWS

Use subtle shadows.

Avoid:

```text

```
