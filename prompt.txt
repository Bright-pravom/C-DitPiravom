# AGENT PROMPT — Visual Polish Pass for the C-DIT Website

You are a senior front-end designer/engineer improving the **visual quality** of an existing static site (`/website`) without changing its structure, content, or functionality. This is a polish pass, not a rebuild: keep every page, section, route, and piece of real content exactly where it is. Do not touch business logic (forms, filters, data.js) except where explicitly noted below.

A set of ready-made assets is provided in `/ui-assets` (icons, one hero illustration, two background patterns). Use them — don't generate new emoji or clip-art in their place.

```
/ui-assets
├── icons/
│   ├── services/        (website-creation, student-guidance, project-support, digital-creative)
│   ├── why-us/           (practical-learning, beginner-friendly, hands-on-practice, guidance, local-accessible)
│   └── contact/          (phone, email, location)
├── illustrations/
│   └── hero-learning.svg
└── patterns/
    ├── dot-grid.svg      (tileable background texture)
    └── corner-glow.svg   (soft radial accent, use behind sections sparingly)
```

All icons are stroke-based, `stroke="currentColor"`, no fill except small accent dots — so they inherit whatever color you set via CSS (`color: var(--primary)` etc.) and can be recolored per section without editing the SVGs.

## 1. Replace emoji icons with the provided SVG set

Currently `index.html` (and the equivalent service/why-us markup on other pages) uses raw emoji (`🌐`, `🎓`, `💻`, `🎨`, `🧠`, `🤝`, `🛠️`, `🌱`, `📍`, `☎`, `✉`) inside `.icon` / `.contact-icon` divs. Emoji render inconsistently across OS/browsers and look inconsistent next to a designed UI.

- **Services section** (`.service-card .icon`): swap in, in order —
  `website-creation.svg` → Website Creation, `student-guidance.svg` → Student Guidance, `project-support.svg` → Project Support, `digital-creative.svg` → Digital & Creative Services.
- **Why Us section** (`.why-card .icon`): `practical-learning.svg`, `beginner-friendly.svg`, `hands-on-practice.svg`, `guidance.svg`, `local-accessible.svg` — in the same order as the existing cards.
- **Contact cards** (`.contact-icon`): `phone.svg` for Call/Phone, `email.svg` for Email, `location.svg` for Address. Leave the WhatsApp icon as-is (it already uses the existing `assets/icons/whatsapp.svg`).
- Inline the SVG markup directly into the HTML (don't `<img>` them) so `currentColor` and `stroke` styling work, and so they inherit hover-state color transitions.
- Give each `.icon` / `.contact-icon` container a fixed size (e.g. `40–48px`), a soft tinted background circle or rounded-square (`var(--primary-pale)` / `var(--primary-light)`), and center the icon inside at roughly 55–60% of the container size — this is the "icon badge" look, not a bare icon floating in space.
- On hover of the parent card, transition the icon badge's background from the pale tint to the full primary color and the icon stroke from `var(--primary)` to `#fff` (a filled-badge hover state). Keep the transition under 200ms.

## 2. Replace the placeholder hero graphic

The current hero (`.hero-visual`, `.hero-frame`, `.bg-blobs`, `.device`) is built entirely from empty CSS boxes standing in for a "device with code bars." Replace this with `illustrations/hero-learning.svg`.

- Drop the SVG in as an inline `<svg>` (or `<img>`) inside `.hero-visual`, sized to fill the existing hero-visual column responsively (`width: 100%; height: auto;`).
- Keep (or lightly restyle) the three floating info cards ("Practical Learning," "Hands-on Training," "Student Guidance") as an overlay on TOP of the illustration using `position: absolute`, rather than as separate boxes — the illustration already includes matching floating-card shapes at roughly the right positions to align with; nudge your absolutely-positioned real HTML cards to sit near those illustrated card outlines for a layered effect.
- Add a slow, subtle floating animation to the illustration itself (`translateY` oscillating ±6px over 4–6s, `ease-in-out`, infinite) — guard it under `prefers-reduced-motion: reduce` (set `animation: none`).
- Remove the now-unused `.bg-blobs`, `.device`, `.device-header`, `.device-body`, `.code-bars`, `.code-bar`, `.code-pill`, `.lesson-row`, `.lesson-box` CSS once nothing references them, to keep the stylesheet clean.

## 3. Add restrained texture to flat sections

Right now, alternating sections just swap between `var(--surface)` and white. Add quiet depth without introducing clutter:

- On the hero section only, place `patterns/corner-glow.svg` as a full-bleed background image behind the content (`background: url(...) no-repeat; background-size: cover;`), sitting behind the illustration and copy, at low opacity if needed. This should read as ambient light, not a visible sticker.
- On the "More Than Just Computer Classes" and "Why Learn With Us?" section backgrounds, tile `patterns/dot-grid.svg` at very low density (`background-image: url(...); background-size: 22px 22px;`) instead of (or blended under) the current flat `var(--surface)` fill. Keep it barely visible — this is meant to add texture on close inspection, not be a visible dot pattern from a normal viewing distance.
- Do not apply any pattern behind text-heavy areas (course grid, contact form, footer) — patterns belong only in low-text hero/section-header zones.

## 4. Typography pass

The site currently uses a single weight-heavy sans (`Inter`) for everything, including large display headings, which reads a little flat/corporate for an education brand.

- Keep `Inter` for body text, labels, buttons, and UI chrome (it's a good, legible workhorse font — don't change it everywhere).
- Add one **serif or humanist display face** for `h1`/`h2` section headings only (e.g. `Fraunces`, `Source Serif 4`, or `Newsreader` from Google Fonts — pick one and use it consistently). This single addition does more than any color change to make the site feel like a considered brand rather than a template.
- Increase the size contrast between `h1`/hero heading and body copy — the hero `h1` should feel noticeably large and confident (`clamp(2.4rem, 5vw, 3.6rem)` is a reasonable target), with generous `line-height` (1.05–1.15) and slightly negative `letter-spacing` (`-0.01em` to `-0.02em`) at that size.
- Tighten `.eyebrow` styling: keep it small and uppercase, but confirm consistent letter-spacing (~0.06em) and a distinct accent color (`var(--primary)` or the secondary cyan) across every section — right now it's mostly consistent, just verify no section was missed.

## 5. Card and button micro-interactions

- **Course cards / recommended cards / service cards / why-cards:** on hover, apply a combined `transform: translateY(-4px)` + increased `box-shadow` + (for cards with an image) a `transform: scale(1.04)` on the inner `<img>` only, clipped by `overflow: hidden` on the card, with a `transition` of `250–300ms ease`. Confirm every card type gets this consistently — right now some cards may only have a shadow change.
- **Primary buttons (`.btn-primary`):** add a subtle `transform: translateY(-2px)` and shadow lift on hover/focus-visible (in addition to the existing background-color change), so the CTA feels tactile, not just recolored.
- **Nav links:** add an animated underline — a `::after` pseudo-element, `width: 0` to `100%` on hover, `transition: width 200ms ease`, positioned under the link text — rather than only a background/color swap.
- **Course-detail "modules" checklist:** stagger-animate each `<li>` in with a short `translateX(-8px)→0` + fade as it scrolls into view, 40–60ms delay between items, so the list feels assembled rather than dumped in at once.
- Respect the existing `prefers-reduced-motion` block — every animation/transition you add must also be covered there (either by adding the new selectors to the existing reduced-motion rule, or by scoping new transforms behind `@media (prefers-motion: no-preference)`).

## 6. Spacing and rhythm

- Audit vertical spacing between sections: confirm a consistent rhythm (e.g. all `.section` = 88–96px top/bottom on desktop, `.section-small` = 56–64px), and that this scales down proportionally on mobile (e.g. 56px / 40px) rather than staying fixed.
- Increase the gap between `.section-header` and the content grid below it slightly (currently tight) — aim for enough whitespace that the heading reads as a clear section title, not crowded by the first card row.
- On the contact panel (`.contact-panel`), increase internal padding on desktop and consider a very subtle bordered inner divider between the info column and the form column (a 1px `var(--border)` vertical rule with generous gap either side) rather than relying on the grid gap alone to separate them.

## 7. Image treatment (once real photography replaces the current stock images — see the separate content-fix prompt)

- Standardize every content image (`course-card img`, `gallery-item img`) to a consistent `aspect-ratio` via CSS (not just fixed width/height attributes) so cards align in a clean grid even before images finish loading — prevents layout shift.
- Add a very subtle `border-radius` matching the card's own radius on all images (`border-radius: inherit` if the image is a direct child of a rounded container, or match the token explicitly).
- Add a soft `box-shadow` only to standalone hero/illustration imagery, not to every grid thumbnail — grid images should rely on the card's shadow, not stack their own on top.

## 8. Mobile-specific polish

- Confirm the mobile nav drawer opens with a slide/fade transition (not an instant `display: block` toggle) and that a translucent backdrop appears behind it so it reads as an overlay, not a page reflow.
- On touch devices, add a brief `:active` scale-down (`transform: scale(0.97)`, ~100ms) to buttons and course cards, since `:hover` states won't fire — this gives tap feedback that's currently missing on mobile.
- Verify the floating WhatsApp button (`.whatsapp-floating-button`) sits clear of the mobile safe-area inset at the bottom (`bottom: calc(20px + env(safe-area-inset-bottom))`) so it doesn't collide with a phone's gesture bar.
